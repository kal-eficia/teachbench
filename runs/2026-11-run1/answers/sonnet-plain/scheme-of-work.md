# Year 8 computing: Python basics, half-term plan

## Assumptions
- 12 lessons of 50 minutes (6 weeks x 2). Assessment in Week 6, Lesson 2, so there are 11 teaching lessons including a consolidation one.
- Students have used Scratch but never typed code. Computers are available, with Python (Thonny, IDLE, or an online editor such as Trinket or Replit) set up and tested before Lesson 1.
- Mixed attainment class of around 25 to 30.

## Overall approach
Each lesson uses a "see, modify, make" cycle: run working code, change it, then write something new. Typing accuracy is a barrier for beginners, so teach the common error messages early and build confidence with quick wins. Connect to Scratch ("a forever loop becomes a while loop") but do not rely on it too heavily.

## Learning sequence

| Wk | Lesson | Focus | Main activity |
|---|---|---|---|
| 1 | 1 | Hello Python: print, typing, errors | Type and run `print`. Predict output. Spot syntax errors (missing bracket, quote, capital P). |
| 1 | 2 | Variables and data types | Store and print name, age. Strings, integers. Link to Scratch variables. |
| 2 | 3 | Input and string joining | `input()` to ask questions, build a "mad libs" story. |
| 2 | 4 | Numbers and calculations | `+ - * /`, integers vs strings from `input`, `int()`. Simple calculator, tip or area program. |
| 3 | 5 | Selection: if / else | Comparison operators, indentation. Guess-the-number-style checks, age checker. |
| 3 | 6 | Selection: elif and logic | Multi-branch quiz questions, `and` / `or`. Build a short quiz with scoring. |
| 4 | 7 | Iteration: for loops | `for i in range()`. Times tables, countdown. Link to Scratch repeat. |
| 4 | 8 | Iteration: while loops | Password checker, guessing game that repeats until correct. |
| 5 | 9 | Debugging and tracing | Fix broken programs. Trace with a table. Syntax vs logic errors. |
| 5 | 10 | Mini-project, part 1 | Plan and build a quiz or game using input, selection and iteration. |
| 6 | 11 | Mini-project, part 2 and revision | Finish, test, comment code. Quick revision quiz on key terms. |
| 6 | 12 | Assessment | See below. |

## Lesson shape (50 minutes)
- 5 min: starter, a retrieval question or a "what does this print?" prediction.
- 10 min: teacher live-codes, makes deliberate mistakes, and students predict outcomes.
- 25 min: guided tasks on a graded sheet (core, then extension). Pairs for debugging, individuals for writing.
- 5 min: plenary, share one error fixed.
- 5 min: exit question (one-line written check) and save work.

## Helping students who have never typed code
- Short, graded tasks with a visible success: the program does something in under five minutes.
- A "common errors" poster: missing quote, wrong case, missing colon, wrong indentation, `=` vs `==`.
- Printed reference sheet of every command taught, kept in books.
- Pair programming: one types, one reads, then swap.
- Starter code with gaps (Parsons-style or fill the blanks) for students who need more support.
- Extension: add features (score, difficulty levels, random module).

## Assessment (Week 6, Lesson 2)
Two parts, about 50 minutes in total:
1. Short written or on-screen quiz (15 minutes): predict output, name data types, identify and fix an error, say what a loop or `if` does.
2. Practical task (35 minutes): write a program from a short brief, for example "ask the user for their name and score out of 10, then print a message depending on the score, and repeat for three players". Success criteria: uses input, a variable, selection, a loop, and has comments.

Mark with a simple rubric (works, uses each construct, tested, commented), and leave 5 minutes at the end for them to test their own work.

## Checking progress along the way
- The lesson 4, 8 and 9 tasks double as formative checkpoints. Note who is not yet writing independently and give them a short catch-up with scaffolded code.
- Keep a class error log of the most common mistakes and use it for starters.

## Resources to prepare
- Pre-written starter files for each lesson, with some containing deliberate bugs
- Reference sheet and error poster
- Assessment brief, mark scheme and a model solution
