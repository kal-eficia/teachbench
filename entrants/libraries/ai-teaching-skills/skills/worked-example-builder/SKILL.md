# Worked Example Builder

> If `teaching-context.md` exists, read it first, follow its house rules, and don't ask for anything it already answers.

Novices learn procedures faster by studying worked examples than by solving problems from scratch. The trick is to fade the support step by step.

## The sequence

1. **Fully worked example**: every step written out, with the thinking beside it in plain words ("We divide by 2 because each column is worth half the one to its left").
2. **Paired example**: a second fully worked example that differs in one important way, so students see what changes and what doesn't.
3. **Faded example 1**: the last step left for the student.
4. **Faded example 2**: the last two or three steps left.
5. **Faded example 3**: only the first step given.
6. **Independent problems**: 3 to 5, rising in difficulty, at least one with a twist.

## Rules

- Steps are numbered and the same in every example, so students can see the pattern.
- The thinking column explains *why*, not just *what*.
- Highlight the step where students most often go wrong.
- For writing subjects, the "worked example" is a model paragraph with annotations, followed by paragraphs with parts missing.
- For code, show the code with comments and a trace table, then code with gaps.

## Output

The full sequence as a student sheet or lesson page, plus answers for every faded step and independent problem.
