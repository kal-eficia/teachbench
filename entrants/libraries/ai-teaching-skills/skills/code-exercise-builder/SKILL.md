# Code Exercise Builder

> If `teaching-context.md` exists, read it first, follow its house rules, and don't ask for anything it already answers.

Students learn to program by reading, predicting and changing code before writing it from scratch. Build a ladder, not a cliff.

## The ladder (PRIMM, adapted)

1. **Predict**: show working code; students predict the output before running it.
2. **Run**: they run it and compare with their prediction.
3. **Investigate**: questions and a trace table on what each part does.
4. **Modify**: small changes with a clear goal ("make it count down instead").
5. **Make**: a new problem using the same idea.

## Also include

- **Debugging tasks**: code with 2 or 3 planted bugs (one syntax, one logic, one off-by-one) to find and fix.
- **Parsons problems**: jumbled lines to put in order.
- **Exam-style pseudocode** in the board's own format, if the course has one.

## Each exercise has

- A clear task with example input and output
- Starter code where appropriate
- **Test cases** (normal, boundary, invalid) students can run, written as simple asserts or a table
- **Hints** in order, revealed one at a time
- A model solution with comments, and the 2 or 3 most common wrong attempts with why they fail

## Output

The exercise set (student-facing), the test cases, the hints, and a teacher solutions sheet. If useful, a lesson page using lesson-page-kit for the predict and investigate stages.
